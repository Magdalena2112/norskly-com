- Keep country-specific Relocation Hub guidance in separate typed data modules and render it only for its selected country, because content and rules must not leak between Norway and Germany.
- Link mutable immigration and tax guidance to official sources and avoid unverified fixed figures, because rules and fees can change.
- Keep Relocation Hub credibility labels in a reusable status component with per-country review dates, so each guide can be updated independently.
- Keep `/relocation-hub` as the country selector and render `/relocation-hub/:countryId` from the shared roadmap, so country-specific links stay stable without duplicating guidance.
- Listening activities are data rows (`listening_activities`) graded through the type registry in `src/lib/listening.ts`, and progress is scoped per language, so new activity types or courses can be added without rebuilding the module.
- Pronunciation activities are per-language data rows (`pronunciation_activities`) with types/categories registered in `src/lib/pronunciation.ts`, progress scoped per language, and optional course/chapter/lesson ids, so content and lesson links can be added later without UI changes.
- Roles are separate: `admin`/`admin_teacher` (platform control), `teacher` (own workspace under `/teacher/*`, only students with lessons booked with them via `current_teacher_id()`/`teacher_has_student()`), `student`; teachers skip student onboarding, because each role must see only its own data.
- Teacher access is granted by admin approval (`approve_teacher_application` creates the teacher profile) plus `claim_teacher_account()` for verified emails via `/profesori/aktivacija`, because roles must never be granted to unverified addresses.
- Teacher notes and homework (`teacher_lesson_notes`, `teacher_assignments`) are scoped per language, because teachers may teach several languages and content must not mix.
